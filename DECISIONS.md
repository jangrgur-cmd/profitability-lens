# Decision log

Every non-trivial choice made while building this project, and who made it.
"Claude" means the choice was made by the AI coding assistant (Claude Code) and is open for review by Jan Grgur Glivar.

| Date | Decision | Decided by | Why |
|---|---|---|---|
| 2026-11-23 | Used a seeded PRNG (mulberry32, seed in `assumptions.json`) for all randomness in the generator | Claude | Same inputs always produce the same `traffic.json`, so numbers in the dashboard, README and memo are reproducible |
| 2026-11-23 | `assumptions.json` holds every number the generator uses: assumptions (with id, value, unit, source, status, note), plus customer list and generator parameters | Claude | One file to review and source; the generator only contains combination logic |
| 2026-11-23 | Initial placeholder values were produced once from a few base tables (cost per route, markup per channel, category price multipliers); `assumptions.json` is now edited directly | Claude | Hand-writing ~400 entries is error-prone; the base tables are not kept, so there is a single source of truth |
| 2026-11-23 | Customer list price is a single list price per country × channel × category; the customer discount is applied in the calculation, not stored in traffic rows | Claude | Matches the spec formula `revenue = volume × price × (1 − discount)` and lets scenarios change prices and discounts independently |
| 2026-11-23 | Discount tier is fixed per customer, set from its base monthly volume (tiers 0 / 5 / 10 / 20 %, thresholds 0.5M / 2M / 8M messages per month) | Claude | Simple and explainable; recalculating tiers each month would add noise without changing the story |
| 2026-11-23 | Customer volumes follow a power law by rank (top customer 25M msgs/month, exponent 1.3) | Claude | Produces the long tail asked for: the top 3 customers carry roughly 60 % of volume |
| 2026-11-23 | Customers use a subset of countries and channels depending on size tier (Enterprise: 6–9 countries, all channels; SMB: 1–2 countries, mostly SMS) | Claude | Realistic and keeps `traffic.json` under 2 MB (about 8,300 rows, 1.6 MB) |
| 2026-11-23 | Voice carries authentication traffic only (voice OTP); other channels follow the customer industry's category mix | Claude | Voice is used in practice for OTP fallback, not marketing |
| 2026-11-23 | Category mix depends on customer industry (e.g. banking is OTP-heavy, retail is marketing-heavy) | Claude | Makes customers differ in a way an analyst can explain; added as an assumption group beyond the spec's list |
| 2026-11-23 | WhatsApp fees, and SMS/Voice costs in the US and Mexico, are denominated in USD; everything else in EUR | Claude | About a third of delivery cost is in USD, so the EUR/USD scenario has a visible effect |
| 2026-11-23 | Target gross margin range 20–26 %; default markups raised so the generated baseline is about 22 % (was 18–28 % and about 19 %) | Frost (range), Claude (markup tuning) | Listed European messaging-heavy CPaaS companies reported roughly 22–24 % gross margin in 2024; the model also deducts a platform cost per message, so low-20s is a fair baseline. Sources still to be verified and recorded in `assumptions.json` |
| 2026-11-23 | Built-in problems for the analysis: four loss-making routes, one top-2 customer at single-digit margin after its 20 % discount, thin margins on high-volume competitive SMS routes | Claude | Required by the spec so the dashboard has something real to discover; not labelled anywhere in the UI |
| 2026-11-23 | Two small customers are gross-margin loss-makers through their traffic footprint, not through special pricing: Copperleaf Telecom (mostly Nigeria SMS, priced below termination cost) and Zephyr Couriers (WhatsApp-only notifications in India, where the Meta fee is so low that the fixed platform cost per message exceeds the markup). Set via an optional `footprint` on the customer in `assumptions.json` | Frost (asked for realistic loss-makers), Claude (mechanism) | Realistic at gross-margin level: losses come from route mix, so the whale curve peaks only slightly above 100 % (about 100.2 %). Larger overshoots would need cost-to-serve, which this model does not include |
| 2026-11-23 | Fixed footprints that include Croatia for four customers: Harbor & Pine Travel (UK, Germany, Croatia, Turkey), Fernhill Grocers (Croatia, Slovenia; SMS and Viber), Evergreen Dental (Croatia, SMS) and Arcadia Play (Germany, Croatia, SMS) | Frost (asked for wider Croatia coverage), Claude (which customers) | Croatia had customers in only 4 of 8 industries, so the Croatian view looked thin; it now has 9 customers across all 8. Side effect of the reshuffle: Lighthouse Finance (Nigeria SMS only) became a third small loss-maker (about −3 %), kept because it follows the same Nigeria pricing mechanism |
| 2026-11-23 | `traffic.json` is written one row per line | Claude | Compact enough, and git diffs stay readable when assumptions change |
| 2026-11-23 | Added `tests/generator.test.mjs` (not in the original structure) for determinism and data integrity | Claude | M1 requires determinism tests; `tests/calc.test.mjs` is reserved for calculations (M2) |
| 2026-11-23 | `calc.js` functions take an explicit context (`eurUsd`, `discountByCustomer`) instead of reading globals | Claude | Keeps every calculation pure and testable, and lets the scenario engine pass a different FX rate without changing the rows |
| 2026-11-23 | Ratios that divide by zero (margin on zero revenue, per-message figures on zero volume) return `null`, shown as "n/a" | Claude | Spec rule for margin; applied the same way to per-message averages |
| 2026-11-23 | "Cost per message" includes both delivery cost and platform cost | Claude | Matches how gross profit is defined, so revenue per message − cost per message = profit per message |
| 2026-11-23 | Row filtering for the global filter bar lives in `calc.js` (`filterRows`) | Claude | It is pure logic and needs unit tests; `main.js` will only hold filter state |
| 2026-11-23 | `calc.test.mjs` also reconciles the real data (sum by country = by channel = by customer = total) and checks the baseline margin against the target range | Claude | Catches assumption edits that break the totals or push the margin out of range; the Data checks tab (M6) will show the same checks in the UI |
| 2026-11-23 | Overview opens with a plain-English sentence that rewrites itself with the filters ("Full model year, all traffic: €7.3M gross profit on €32.8M revenue, a 22.1% margin."), followed by a row of five KPIs instead of boxed KPI cards | Claude | A recruiter gets the answer in one line; an interviewer gets the figures underneath |
| 2026-11-23 | Light theme on cool off-white, slate ink, one indigo accent for interface state only; profit green and loss brick red always paired with a word or ▼ symbol; channel colours avoid WhatsApp/Viber brand colours | Claude | Spec asks for a calm finance look with one accent and no colour-only meaning; brand colours would clash with the profit colour |
| 2026-11-23 | System fonts (Segoe UI / system sans; a serif only for the headline sentence), not Google Fonts | Claude | Loading Google Fonts sends each visitor's IP address to Google, a known GDPR issue in the EU; system fonts also keep the page dependency-free |
| 2026-11-23 | Channel mix chart shows each channel's share of messages, revenue and gross profit as three 100 % bars; the gross-profit bar is left empty (with a note) when a channel is loss-making in the selection | Claude | Shows at a glance whether a channel earns more or less than its share of traffic; profit shares are meaningless when one part is negative |
| 2026-11-23 | Chart animations turned off | Claude (bug found by Frost) | Chart.js animations crashed when a value changed type between updates (number → null), which froze the charts after a few filter changes; instant updates also suit a finance tool |
| 2026-11-23 | Filter options with no traffic given the other filters are greyed out and labelled "(no traffic)" | Claude (issue found by Frost) | With 30 customers many country × industry combinations are empty (e.g. no retail customer sends traffic to Croatia); picking them gave an empty page with no explanation |
| 2026-11-23 | Gross margin axis on the trend chart starts at 0 % | Claude | An auto-zoomed axis (22.2–22.4 %) made a flat margin look volatile |
| 2026-11-23 | URL hash only stores settings that differ from the defaults; invalid values fall back to defaults; filter changes replace the history entry rather than adding one | Claude | Clean default link, shareable views, and old or broken links still open a working page |
| 2026-11-23 | Added `js/format.js` (number formatting) and `js/state.js` (URL state), plus `tests/ui-logic.test.mjs` | Claude | Pure helpers kept out of `main.js` so they can be unit-tested without a browser |
| 2026-11-23 | Chart.js v4.4.7 (MIT) saved as `lib/chart.umd.min.js` | Claude, download approved by Frost | Spec requires a local copy; 4.4.7 is a stable release |
| 2026-11-23 | `.gitattributes` forces LF line endings | Claude | The test that compares committed `traffic.json` with a fresh generation is byte-exact and would fail on Windows checkouts with CRLF |
