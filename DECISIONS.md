# Decision log

Every non-trivial choice made while building Profitability Lens, and who made it.
"Claude" means the choice was made by the AI coding assistant (Claude Code) and is open for review by Jan Grgur Glivar.
Decisions about the messaging case study before it joined this repo are in [`modules/messaging/DECISIONS.md`](modules/messaging/DECISIONS.md).

| Date | Decision | Decided by | Why |
|---|---|---|---|
| 2026-11-24 | Default branch is `main` | Jan | Matches the messaging repo and GitHub's default |
| 2026-11-24 | `CLAUDE.md` (project rules for Claude Code) is tracked in git | Jan | Documents how the project was built with Claude Code |
| 2026-11-24 | The messaging dashboard is brought in with `git subtree add` (full history, not squashed) into `modules/messaging/` | Jan (keep history), Claude (method) | Keeps its 23 commits and their authorship; no copy-paste |
| 2026-11-24 | Characterisation ("golden") tests snapshot every number the messaging dashboard shows (totals by country, channel, category, month, route and customer; whale curve; a filtered selection; the three presets; a scenario that moves every lever; data checks; number formatting) into `modules/messaging/tests/golden/expected.json` | Jan (tests before refactoring), Claude (scope) | Proves the Phase 1 refactor into `src/shared/` changes nothing a user can see |
| 2026-11-24 | Golden comparison uses a relative tolerance of 1e-12 | Claude | Allows floating-point differences when a refactor sums in a different order, but one extra message (≈ €0.03 on €112M) still fails |
| 2026-11-24 | `docs/assumptions.md` is generated from `assumptions.json` by `scripts/build-assumptions-doc.mjs`, and a test fails if it is out of date | Claude | One source of truth: the document can never disagree with the dashboard |
| 2026-11-25 | `src/shared/` holds `format.js` (all display formatting), `margin.js` (safe division, benchmark bands and scores) and `parse.js` (typed amounts). The messaging module imports them directly; its own `js/format.js` is deleted, with no re-export shim | Claude | One copy of every formula; the golden tests prove the dashboard's numbers and formats did not change |
| 2026-11-25 | The messaging scenario and route views use the shared `formatSignedPct`, `formatSignedEur` and `formatPp` instead of local helpers | Claude | They duplicated formatting that the rating module also needs |
| 2026-11-25 | `tables.js` and `export.js` stay in the messaging module for now | Claude | Only one module uses them today; they move to `src/shared/` when the Company rating UI or the generalised segment module needs them |
| 2026-11-25 | Number parsing: besides the brief's rule (a lone separator followed by exactly three digits is a thousands separator), a first group of `0` or of more than three digits makes it a decimal (`0,125`, `1234.567`), and after space grouping a lone separator is decimal (`1 234,567`) | Claude | Thousands groups cannot start with 0 or have four digits; the brief's rule alone would read `0,125` as 125 |
| 2026-11-25 | Blank optional amounts count as 0, except COGS, current liabilities and debt, which make their ratio "missing". Blank cash counts as 0 | Claude | A blank cost line usually means "none"; the three exceptions are the inputs a ratio cannot do without. Cash 0 gives the more cautious ROIC |
| 2026-11-25 | ROE (and the DuPont equity multiplier) is not meaningful when year-end **or** average equity is zero or negative | Claude | Textbook: a return on negative capital has no meaning. A positive average could otherwise hide negative year-end equity. Flagged for Jan's review |
| 2026-11-25 | ROCE and ROIC use year-end capital; ROA and ROE use averages when a prior year is given | Claude (following the brief's formulas) | As specified in CLAUDE.md §4.2; noted in docs/methodology.md as a possible refinement |
| 2026-11-25 | Effective tax rate clamped to 0–50 % for NOPAT, so a tax credit never raises NOPAT above EBIT | Claude (following the brief) | Keeps one-off tax items from distorting ROIC |
| 2026-11-25 | Overall score is rounded to a whole number and the grade is taken from the rounded score | Claude | The grade always matches the number the user sees (no "80/100, grade B") |
| 2026-11-25 | Flag details: interest-cover flag only when there is interest expense; operating-loss flag only when COGS is given; depreciation flag only when EBITDA is positive; the low-coverage flag fires when only the three required fields are given (55 % of the weight) | Claude | Each rule needs its inputs to be meaningful; a rating on required fields alone deserves a warning |
| 2026-11-25 | First rule-of-thumb thresholds for the seven industries (in `src/rating/benchmarks.js`) were set by Claude | Claude — **to be reviewed by Jan** | Judgement-based starting points, labelled as such in code and docs; calibration against published sector data is on the roadmap |
| 2026-11-25 | Three fictional examples: a bakery (manufacturing, grade B), a hotel with costs by nature and heavy debt (tourism, C) and a loss-making software start-up without prior year (software, E) | Claude | Together they exercise missing COGS, every serious flag, leverage, heavy depreciation and missing prior-year data |
| 2026-11-25 | The rating methodology is documented in `docs/methodology.md` | Claude | CLAUDE.md asks for a methodology section; the Phase 2 "How the rating works" panel will summarise it |
